# @sirius-ui/website

Website framing and content sections composed with SiriusUI. The private preview has Home, About, Projects, Project detail, Contact, Services, Service detail, Pricing, FAQ, Blog, and Article pages in `apps/website`, under the fictional Acme Studio brand.

For agents building an application, start with the [agent guide](../../docs/agent-guide.md) and [website patterns](../../docs/website-patterns.md). This package is a private source-workspace preview at version 0.0.0; do not assume registry availability. Component contracts below describe this checkout.

## Setup

Import public components from `@sirius-ui/website`. Import `@sirius-ui/vue/style.css` and `@sirius-ui/website/style.css` once in the consuming app entry. Compiled CSS includes semantic tokens and utilities without Preflight. Applications own resets, fonts, appearance, content, routes, and requests.

```vue
<script setup lang="ts">
import { SButton } from '@sirius-ui/vue'
import { SWebsiteLayout, SWebsiteHeader, SWebsiteHero } from '@sirius-ui/website'
const links = [{ id: 'home', label: 'Home', href: '/' }]
</script>

<template>
  <SWebsiteLayout main-labelledby="home-title">
    <template #header="{ contentId }">
      <SWebsiteHeader :items="links" current="home" :content-id="contentId">
        <template #brand><a href="/">Acme</a></template>
      </SWebsiteHeader>
    </template>
    <SWebsiteHero title-id="home-title" title="Thoughtfully made." description="A little space for a good idea." variant="centered">
      <template #actions><SButton href="/contact">Get in touch</SButton></template>
    </SWebsiteHero>
  </SWebsiteLayout>
</template>
```

## SWebsiteLayout

| API | Contract |
| --- | --- |
| `contentId` | Optional main landmark ID. A unique ID is generated by default |
| `mainLabelledby` | Optional ID of the page heading naming the main landmark |
| `skipLinkLabel` | Defaults to Skip to content |
| `#header="{ contentId }"` | App-owned header. Pass contentId to SWebsiteHeader for navigation focus handling |
| Default slot | Page content, including its single h1 |
| `#footer` | App-owned footer |

The layout supplies a visible-on-focus skip link and a focusable main landmark. It owns no routing or preference state. Native attrs/class/style apply to its outer div.

## SWebsiteHeader

| API | Contract |
| --- | --- |
| `items` | Required readonly SWebsiteNavItem array |
| `current` | Optional item ID. Matching links receive aria-current=page |
| `navigationKey` | Optional string or number. Change it after a successful route change to close mobile navigation |
| `contentId` | Optional main target for focus after navigation or desktop resizing closes the drawer |
| `linkAs` | Native a by default, or an app-owned href-compatible link component |
| `navigationLabel` | Defaults to Main navigation |
| `openLabel` / `closeLabel` | Defaults to Open navigation / Close navigation |
| `#brand` | Branding and a home link |
| `#actions="{ close }"` | Optional header actions. Rendered in desktop and mobile contexts |
| `select(item, event)` | Emits the selected record and original MouseEvent without preventing navigation |

SWebsiteNavItem is `{ id, label, href, target?, rel?, linkProps? }`. IDs must be unique. Native link behavior preserves modified clicks and new-tab actions. The component closes the mobile drawer after an ordinary, unprevented activation. If an app prevents navigation while routing, use navigationKey to close after success. Pass the scoped close callback to app-owned actions when appropriate.

Desktop navigation appears from 64rem. Below that breakpoint, the trigger opens a native-modal SDrawer on the right. Escape/backdrop dismissal restores opener focus. Navigation and desktop resizing close it and focus contentId after exit. Listeners are removed on unmount. Header attrs/class/style apply to its native header. Keep action-slot state in the app because the slot renders in both desktop and open mobile regions.

## SWebsiteFooter

- Grouped navigation uses one column on narrow screens, two from 40rem, and three from 64rem, with branding beside it at desktop widths.
- `groups` is an optional readonly SWebsiteNavGroup array. Each group is `{ id, label, items }`, using SWebsiteNavItem records. Group IDs must be unique.
- `linkAs` selects a native anchor by default or an app link adapter.
- `#brand` holds branding. Default slot holds supporting copy. `#bottom` holds copyright or secondary content.
- Group labels name their navigation regions using unique per-instance IDs. Links follow native browser behavior. The footer owns no models or emitted events.
- `headingLevel` controls grouped navigation headings, defaulting to 2 and accepting 2–6. Set it to 4 when rendering a grouped footer beneath a showcase example heading.
- `variant` accepts `columns` (default, preserving the existing grouped layout) or `centered`. Centered uses `items` for its flat navigation and `socials` for optional social destinations, both readonly SWebsiteNavItem arrays. Group records are only rendered by columns; flat items/socials are only rendered by centered.
- `navigationLabel` and `socialLabel` name centered navigation regions, defaulting to Footer navigation and Social links. Supply localized/descriptive labels when needed.
- `#socialIcon="{ item }"` supplies each centered social link’s decorative icon. Link labels remain available to assistive technology. Without this slot, social labels render visibly, so links remain usable without an icon set. Keep icon slots noninteractive.
- Centered also supports optional brand/supporting-copy slots and centers bottom content. Navigation, social links, and copyright content wrap on narrow screens. Each social link forwards href, target, rel, and linkProps through linkAs. Branding, icon choice, destinations, and copyright/year text belong to the app.

```vue
<SWebsiteFooter variant="centered" :items="footerLinks" :socials="socialLinks">
  <template #socialIcon="{ item }"><component :is="socialIcons[item.id]" /></template>
  <template #bottom>© 2026 Acme Studio</template>
</SWebsiteFooter>
```

The consuming app owns footerLinks, socialLinks, and socialIcons. See [the centered footer example](../../apps/website/src/components/StudioFooterExamples.vue). The main demo footer retains the default columns layout.

## SWebsiteHero

- `title` is required. `headingLevel` defaults to 1 and accepts 1–4, allowing a hero to be embedded in a section showcase with the appropriate heading level. `titleId` optionally overrides the generated heading ID so the surrounding main can reference it.
- `description` and `eyebrow` are optional text.
- `variant` accepts `split` (default), `centered`, `mobile`, or `angled`. Split places supplied media beside the text at desktop widths. Centered places media below the copy. Mobile adds a subtle grid and phone frame around the media slot. Angled clips the right-hand media edge diagonally on desktop and stacks media beneath the text on smaller screens. A hero without media centers its text.
- For `mobile`, supply screen content only through `#media`, with an accessible image description. The frame has a fixed portrait aspect ratio and clips overflowing content. For `angled`, supply full-height, cover-fit media and keep important visual content away from the clipped edge. Keep credits outside the clipped media.
- `#announcement` optionally holds an announcement link above the eyebrow and heading. Navigation stays in SWebsiteHeader.
- `#title` replaces the inline content inside the heading. Keep it meaningful and consistent with title.
- `#actions` holds app-owned links/buttons. `#media` holds imagery, artwork, or a product preview. Default slot adds supporting content below the actions.
- The hero owns no model or events. Provide appropriate image alternatives and supply optimized assets in the app.

## SWebsiteSection

- `title` is required. `headingLevel` is 2 by default, or 3 / 4 for nested sections.
- `description` and `eyebrow` are optional text.
- `#title` replaces inline heading content. `#aside` holds contextual controls beside the heading. Default slot holds the section body.
- A generated heading ID names the section. It shares the hero's content width and responsive gutters.

| `#media` | Optional app-owned image/product preview. Image variant places it beside the introduction and list at desktop widths |

Small and large icon variants show three columns at desktop widths and stack below 64rem. Grid uses two feature columns from 40rem, with the introduction alongside from 64rem. ## SWebsiteNewsletter

A controlled email subscription section composed from SInput and SButton. Import `SWebsiteNewsletter`, `SWebsiteNewsletterDetail`, and `SWebsiteNewsletterProps` from the package root.

| API | Contract |
| --- | --- |
| `v-model` | Required string containing the email address. Updates on input |
| `title` / `description` | Required heading and optional supporting copy |
| `variant` | `details` (default) or `simple`. Details places its supporting list beside the form from 64rem. Simple places copy beside a form in an accent-soft band |
| `headingLevel` | 2 by default, or 3 / 4 for nested sections |
| `details` | Optional readonly array of `{ id, title, description }`. Unique IDs required. Only rendered by the details variant |
| `emailLabel` / `placeholder` | Defaults to Email address / Enter your email. The label remains available to assistive technology |
| `submitLabel` | Defaults to Subscribe |
| `processing` / `disabled` | False by default. Both disable controls and prevent submit emissions. Processing also marks the form busy and shows the button loading state |
| `error` | Optional server/validation error, announced as an alert and associated with the invalid email control |
| `status` | Optional completion text in a polite live region |
| `#icon="{ detail }"` | Optional decorative detail icon, supplied by the application |
| `#footer` | Optional app-owned privacy link, consent explanation, or supporting content |
| `submit(email)` | Emits the trimmed email string after native form submission. The component does not clear the model |

The email input uses native `type=email`, required, email autocomplete, and a unique associated label. Browser validation runs during ordinary form submission. The form and section reference their own heading. Form controls stack at narrow widths and sit alongside each other from 40rem. The component sends no requests, stores no addresses, and owns no success/error lifecycle. Applications must also validate input on the server, set processing around their request, handle errors, and supply their own actual privacy destination and subscription behavior. Updating the model does not automatically clear app-provided errors or status.

```vue
<SWebsiteNewsletter v-model="email" title="A little inspiration, delivered." variant="simple" :processing="processing" :error="error" :status="status" @submit="subscribe">
  <template #footer><a href="/privacy">Read our privacy policy</a></template>
</SWebsiteNewsletter>
```

The consuming app owns email, processing, error, status, and the subscribe handler. The [newsletter examples](../../apps/website/src/components/StudioNewsletterExamples.vue) keep both models independent and demonstrate a local-only completion message without contacting a subscription service.

## Navigating and extending the section showcase

`#sections` now uses a compact page introduction and an app-owned category menu. The menu sits on the left from 64rem and becomes a horizontally scrollable navigation strip on smaller screens. Links are native anchors with `aria-current=location` for the selected category. They preserve modified clicks, browser history, and direct loading. `#sections/menu` returns focus to the menu; a visible-on-focus skip link jumps directly to the first collection. Each collection also has a return-to-menu link.

Category metadata lives in `apps/website/src/showcaseSections.ts`. The route resolver validates category slugs and supplies a focus target. App navigation focuses and scrolls the matching region after rendering. Targets have tabindex=-1 and scroll margins that account for the sticky mobile menu. Changing category updates the mounted page rather than replacing it, preserving local form and pricing state. The active indicator represents the selected hash category; scrolling alone does not change browser history.
